# CI and GitHub Actions design

## Goal

Every check intj runs — lint, typecheck, tests, benchmarks, image builds — is a
target of `ninja -C ci`. GitHub Actions workflows only pick a container and call
targets; they hold no build logic. The same targets run locally against an
editable checkout and in CI against a freshly built, installed wheel.

## Layout

```
ci/
  AGENTS.md          conventions for ci/
  build.ninja        the only entry point: ninja -C ci <target>
  matrix.json        distro x python cells; single source of truth
  env.sh             sourced by every script: INTJ_MODE, PYTHON, paths, guards
  lint.sh  typecheck.sh  wheel.sh  install.sh
  test-cpu.sh  test-gpu.sh  bench-host.sh  bench-gpu.sh
  image.sh           tag | build | push for one cell
  dockerfiles/
    deb.Dockerfile        ubuntu 22.04, ubuntu 24.04, debian 12
    rhel.Dockerfile       alma 9
    manylinux.Dockerfile  manylinux_2_28 (alma 8)
  out/               build outputs, git-ignored
```

## Ninja

`build.ninja` is a task runner. Every target is `phony` and its rule uses
`pool = console`, so output streams live and the target always reruns. No stamp
files: docker caches layers, and tests must always rerun.

Ninja has no command-line variable overrides, so parameters reach scripts as
environment variables:

| variable | values | default |
|---|---|---|
| `INTJ_MODE` | `editable`, `wheel` | `editable` |
| `PYTHON` | interpreter path | `python` |
| `CELL` | a `matrix.json` cell id, e.g. `ubuntu24.04-py3.12` | — (image targets only) |
| `FLAVOR` | `cpu`, `rocm` | `cpu` |

Targets:

| target | does |
|---|---|
| `lint` | `pre-commit run --all-files` |
| `typecheck` | `pyright` |
| `wheel` | `$PYTHON -m pip wheel --no-deps -w ci/out/dist .` |
| `install` | editable: `pip install -e .`; wheel: install `ci/out/dist/intj-*.whl` |
| `test-cpu` | GPU-free tests (`tests/test_runtime.py` today) |
| `test-gpu` | full `tests/` suite |
| `bench-host` | `bench_launch.py --no-gpu` |
| `bench-gpu` | `bench_launch.py` and `bench_launch.py --readme` |
| `image` / `push-image` | build / build+push the image for `$CELL`, `$FLAVOR` |
| `check` (default) | `lint typecheck test-cpu` |

`install` does not depend on `wheel`: CI builds the wheel once and installs it in
every cell, so locally the pair is `ninja -C ci wheel install`.

## Install modes

`editable` is for development: tests run from the repo root against the
checkout. `wheel` is what CI checks, and must test the installed package, never
the checkout:

- tests run with `ci/out/run/` as the working directory;
- `pytest` is invoked as `$(dirname $PYTHON)/pytest`, not `python -m pytest`
  (which puts the cwd on `sys.path`), and `PYTHONPATH` is unset;
- a preflight in `env.sh` imports `intj` and fails unless `intj.__file__` is
  under the interpreter's `site-packages`.

Benchmarks follow the same rules.

## Matrix

Each distro tests the pythons it packages; `manylinux_2_28` contributes the
versions no distro ships, including free-threaded builds.

| cell distro | pythons | python source |
|---|---|---|
| ubuntu 22.04 | 3.10 | apt `python3.10{,-dev,-venv}` |
| ubuntu 24.04 | 3.12 | apt `python3.12{,-dev,-venv}` |
| debian 12 | 3.11 | apt `python3.11{,-dev,-venv}` |
| alma 9 | 3.9, 3.11, 3.12 | AppStream `python3{,.11,.12}{,-devel}` |
| manylinux_2_28 | 3.8–3.14, 3.13t, 3.14t | `/opt/python/cpXY*` |

15 cells. `matrix.json` lists each cell as
`{"id", "distro", "dockerfile", "base", "python", "gpu"}`; `gpu` is true for
python >= 3.10 (triton 3.8 has no wheels below that). Workflows load it with
`fromJSON`; `image.sh` looks cells up in it by `id`.

## Images

`ghcr.io/lijinpei-amd/intj-ci:<cell>-<flavor>-<hash>`, where `<hash>` is a short
sha256 of the dockerfile plus the cell's JSON entry. A PR that changes a
dockerfile therefore builds and tests its own image.

Each image contains gcc, the python headers, git, ninja, and `/opt/venv` built
from the cell's python, holding torch (CPU or ROCm 7.2 index; the newest the
python can install), triton 3.8 (python >= 3.10), jinja2, tomli (< 3.11),
pytest, pyright and pre-commit. intj itself is never baked in. `PYTHON` defaults
to `/opt/venv/bin/python` inside the image.

`rocm` images exist only for `gpu` cells and are built on the self-hosted runner
(each is ~5 GB; hosted runners have ~14 GB free).

`image.sh tag` prints the tag; `image.sh build|push` build or push it; `push`
first runs `docker manifest inspect` and skips cells already published.

## Workflows

`.github/workflows/ci.yml` — on pull requests and pushes to `main`:

1. `matrix`: emits `ci/matrix.json` as a job output.
2. `wheel`: `ninja -C ci wheel`, uploads `ci/out/dist/` as an artifact.
3. `images` (per cell): `CELL=... ninja -C ci push-image` (cpu flavor), outputs
   the tag.
4. `test` (per cell, `container:` that tag): download the wheel,
   `INTJ_MODE=wheel ninja -C ci install test-cpu`.
5. `lint`, `typecheck`, `bench-host` once, in the ubuntu 24.04 / 3.12 image;
   `bench-host` output uploaded as an artifact.

`.github/workflows/gpu.yml` — `workflow_dispatch` only, `runs-on: [self-hosted,
gfx942]`, over the `gpu` cells: build/push the rocm image, then in it (with
`/dev/kfd`, `/dev/dri`, `--group-add video`) run
`INTJ_MODE=wheel ninja -C ci install test-gpu bench-gpu` and upload the bench
output. Enabling it on PRs later is a trigger change only.

Jobs use `GITHUB_TOKEN` with `packages: write` to push to GHCR.

## Benchmarks

Informational only: no thresholds, since hosted runners are too noisy. Each run
uses `taskset -c 0` and writes `ci/out/bench/<target>.txt`. Recording a result
in `benchmarks/journals/` stays a manual step under `benchmarks/AGENTS.md`.

## Error handling

Scripts use `set -euo pipefail`. A missing wheel in `install`, a wheel-mode
import resolving to the checkout, or an unknown `CELL` exits non-zero with one
line naming the cause.

## Verification

- Locally (editable): `ninja -C ci` passes in the dev venv.
- Locally (wheel): `INTJ_MODE=wheel ninja -C ci wheel install test-cpu` passes, and
  the preflight fails if the wheel is not installed.
- Images: `CELL=<id> ninja -C ci image` builds for one cell of each dockerfile,
  then `ninja -C ci install test-cpu` inside it.
- Workflows: `actionlint` on `.github/workflows/`; first real run on GitHub.
- GPU path: `test-gpu` in a rocm image on this machine's gfx942. The self-hosted
  runner registration itself is untested until one exists.

## Out of scope

Registering the self-hosted runner, CUDA images (no NVIDIA GPU to test on),
publishing wheels to PyPI, benchmark regression thresholds.
