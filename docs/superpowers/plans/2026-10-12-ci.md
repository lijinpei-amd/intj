# CI and GitHub Actions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every intj check is a `ninja -C ci` target, run against an editable checkout locally and against a freshly built, installed wheel in GitHub Actions across a distro x CPython matrix.

**Architecture:** `ci/build.ninja` is a task runner whose targets call small bash scripts sharing `ci/env.sh` (mode, interpreter, wheel-mode guard). `ci/image.py` turns `ci/matrix.json` cells into content-hashed GHCR images built from two dockerfiles. Workflows only pick a container and call ninja targets.

**Tech Stack:** ninja >= 1.10, bash, python3 stdlib (image.py), docker, GitHub Actions, GHCR, pip/uv.

**Spec:** `docs/superpowers/specs/2026-10-12-ci-design.md`

## Global Constraints

- Workflows contain no build logic: every check step is `ninja -C ci <target>`.
- Parameters reach scripts as env vars only: `INTJ_MODE` (`editable` default | `wheel`), `PYTHON`, `CELL`, `FLAVOR` (`cpu` default | `rocm`).
- Wheel mode must never import intj from the checkout.
- CI tests only the wheel built in the same run (`INTJ_MODE=wheel`).
- Image tag: `ghcr.io/lijinpei-amd/intj-ci:<cell>-<flavor>-<hash>`, hash over `ci/dockerfiles/` contents, the cell entry, the flavor and pins.
- `rocm` images only for cells triton 3.8.0 has a wheel for (`"gpu": true`: python 3.10–3.14 and 3.14t; not 3.8, 3.9, 3.13t); triton pinned to `3.8.0`; ROCm torch index `https://download.pytorch.org/whl/rocm7.2`.
- `gpu.yml` is `workflow_dispatch` only, `runs-on: [self-hosted, gfx942]`.
- Benchmarks are informational: no thresholds.
- Outputs live in `ci/out/` (git-ignored).
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

Local environment for every verification step below:

```bash
VENV=/mnt/nvme2/jinpli/workspace/home/jinpli/development/workspace/intj/venv
export PYTHON=$VENV/bin/python   # has torch, triton 3.8, pytest; no pip (uv falls in)
```

## Review Focus

1. Wheel mode importing the checkout (cwd on `sys.path`, `PYTHONPATH`, or an editable install left behind) must fail loudly — pinned in Task 2.
2. `ci/out/dist` holding zero or several wheels must make `install` refuse, not pick one — pinned in Task 2.
3. Reinstalling a same-version wheel must replace stale installed files — pinned in Task 2.
4. Unknown `CELL`, or `FLAVOR=rocm` on a non-gpu cell, must exit with one line naming the cause — pinned in Task 4.
5. Editing any file under `ci/dockerfiles/` must change every tag, so a PR tests its own image — pinned in Task 4.

## Deviations from the spec (Task 6 folds them back in)

- Two dockerfiles, not three: `manylinux_2_28` is alma 8, so `rhel.Dockerfile` with `BASE` covers alma 9 and manylinux. Shared venv setup lives in `ci/dockerfiles/install-venv.sh`.
- manylinux_2_28 no longer bundles CPython 3.8; that cell installs alma 8 AppStream `python38`.
- `image.sh` becomes `image.py` (JSON and hashing in stdlib python); it adds `tag` and `matrix` subcommands; `matrix` writes `ci/out/matrix.json` (ninja's status lines would corrupt stdout).
- Wheel mode runs `$PYTHON -I` (isolated: no cwd/script dir on `sys.path`, `PYTHONPATH` ignored) instead of the `pytest` console script; it covers benchmarks too.
- Ninja does not order command-line targets, so workflows call `install`, then `test-cpu`, as separate steps.
- The `wheel` job uses `actions/setup-python` on the host, so it does not wait for images.
- `gpu` means "triton 3.8.0 has a wheel", not "python >= 3.10": 3.13t has none, so it is a cpu-only cell (11 rocm cells, not 12).

- [ ] **Step 2: Create `ci/env.sh`**

```bash
# Sourced by every ci/ script: resolves the install mode, the interpreter and
# the paths, and runs python against the intj that mode selects.
set -euo pipefail

ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
OUT=$ROOT/ci/out
INTJ_MODE=${INTJ_MODE:-editable}
PYTHON=${PYTHON:-python3}

die() {
  echo "ci: $*" >&2
  exit 1
}

case $INTJ_MODE in
  editable | wheel) ;;
  *) die "INTJ_MODE must be editable or wheel, got '$INTJ_MODE'" ;;
esac
command -v "$PYTHON" >/dev/null || die "PYTHON '$PYTHON' not found"

# pip when the interpreter has it, else uv: uv-created venvs ship without pip.
pip_() {
  if "$PYTHON" -m pip --version >/dev/null 2>&1; then
    "$PYTHON" -m pip "$@"
  else
    uv pip "$1" --python "$PYTHON" "${@:2}"
  fi
}

# Fails unless `import intj` resolves to the interpreter's site-packages.
check_installed() {
  mkdir -p "$OUT/run"
  (cd "$OUT/run" && "$PYTHON" -I -c '
import os, sys, sysconfig
try:
    import intj
except ImportError:
    sys.exit("ci: intj is not installed; run INTJ_MODE=wheel ninja -C ci wheel, then install")
path = os.path.realpath(intj.__file__)
lib = os.path.realpath(sysconfig.get_paths()["purelib"])
if not path.startswith(lib + os.sep):
    sys.exit("ci: intj imports from %s, not from %s" % (path, lib))
print("ci: intj from %s" % path)
')
}

# Runs "$PYTHON" "$@": editable -> the checkout; wheel -> the installed package,
# isolated (-I) from the cwd, the script's directory and PYTHONPATH.
py() {
  if [ "$INTJ_MODE" = editable ]; then
    (cd "$ROOT" && PYTHONPATH=$ROOT "$PYTHON" "$@")
  else
    check_installed
    (cd "$OUT/run" && "$PYTHON" -I "$@")
  fi
}
```

  script = typecheck.sh

- [ ] **Step 5: Create `ci/AGENTS.md`**

```markdown
# ci/

`ninja -C ci <target>` is the only entry point; `.github/workflows/` call
targets and hold no build logic. Design: `docs/superpowers/specs/2026-10-12-ci-design.md`.

## Parameters

Ninja has no command-line variables, so scripts read the environment:

| variable | values | default |
|---|---|---|
| `INTJ_MODE` | `editable` (the checkout, via `PYTHONPATH`), `wheel` (the installed package) | `editable` |
| `PYTHON` | interpreter | `python3`; `/opt/venv/bin/python` in images |
| `CELL` | a `matrix.json` cell id | image targets only |
| `FLAVOR` | `cpu`, `rocm` | `cpu` |

## Targets

| target | does |
|---|---|
| `lint` | pre-commit over all files |
| `typecheck` | pyright |
| `wheel` | builds `ci/out/dist/intj-*.whl` (clears old ones) |
| `install` | editable: `pip install -e .`; wheel: (re)installs the one wheel in `ci/out/dist` |
| `test-cpu` | GPU-free tests |
| `test-gpu` | the full suite |
| `bench-host`, `bench-gpu` | `bench_launch.py`, output in `ci/out/bench/` |
| `matrix` | writes `ci/out/matrix.json` for the workflows |
| `image`, `push-image` | build / build and push the `$CELL`/`$FLAVOR` image |
| `check` (default) | `lint typecheck test-cpu` |

Ninja does not order command-line targets: run `wheel`, `install` and a test
target as separate invocations.

## Rules

- Every script starts with `. "$(dirname "$0")/env.sh"` and runs python via
  `py`, so the mode decides what `import intj` means. Wheel mode runs
  `$PYTHON -I` from `ci/out/run/` and refuses an intj outside site-packages.
- A new check is a script plus a `build` line, then a workflow step calling it.
- Anything that goes into an image is under `ci/dockerfiles/`: every file there
  feeds the tag hash.
```

- [ ] **Step 3: Create `ci/image.py`**

```python
"""Builds and publishes the CI images described by ci/matrix.json.

    python3 ci/image.py matrix                          # writes ci/out/matrix.json
    CELL=<id> [FLAVOR=cpu|rocm] python3 ci/image.py tag|build|push

The tag hashes every file under ci/dockerfiles/, the cell and the pins, so any
change to what goes into an image publishes a new one.
"""

import hashlib
import json
import os
import pathlib
import subprocess
import sys

CI = pathlib.Path(__file__).resolve().parent
DOCKERFILES = CI / "dockerfiles"
REPO = os.environ.get("INTJ_IMAGE_REPO", "ghcr.io/lijinpei-amd/intj-ci")
PINS = {
    "triton": "3.8.0",
    "torch_index": {
        "cpu": "https://download.pytorch.org/whl/cpu",
        "rocm": "https://download.pytorch.org/whl/rocm7.2",
    },
}


def die(message):
    sys.exit("ci: " + message)


def load():
    return json.loads((CI / "matrix.json").read_text())


def tag(cell, flavor):
    digest = hashlib.sha256()
    for path in sorted(DOCKERFILES.iterdir()):
        digest.update(path.name.encode() + b"\0" + path.read_bytes())
    digest.update(json.dumps([cell, flavor, PINS], sort_keys=True).encode())
    return "%s:%s-%s-%s" % (REPO, cell["id"], flavor, digest.hexdigest()[:12])


def selected():
    flavor = os.environ.get("FLAVOR", "cpu")
    if flavor not in PINS["torch_index"]:
        die("FLAVOR must be cpu or rocm, got %r" % flavor)
    cell_id = os.environ.get("CELL", "")
    cells = {cell["id"]: cell for cell in load()["cells"]}
    if cell_id not in cells:
        die("unknown CELL %r; ids are in ci/matrix.json" % cell_id)
    cell = cells[cell_id]
    if flavor == "rocm" and not cell["gpu"]:
        die("CELL %s has no rocm image: triton %s has no wheel for its python" % (cell_id, PINS["triton"]))
    return cell, flavor


def build(cell, flavor):
    args = {
        "BASE": cell["base"],
        "PY_PKGS": cell["py_pkgs"],
        "PY_ENSURE": cell["py_ensure"],
        "PY_BIN": cell["py_bin"],
        "TORCH_INDEX": PINS["torch_index"][flavor],
        "TRITON": PINS["triton"] if cell["gpu"] else "",
    }
    command = ["docker", "build", "-f", str(DOCKERFILES / cell["dockerfile"]), "-t", tag(cell, flavor)]
    for key, value in args.items():
        command += ["--build-arg", "%s=%s" % (key, value)]
    subprocess.run(command + [str(DOCKERFILES)], check=True)


def push(cell, flavor):
    name = tag(cell, flavor)
    exists = subprocess.run(["docker", "manifest", "inspect", name], capture_output=True)
    if exists.returncode == 0:
        print("ci: %s already published" % name)
        return
    build(cell, flavor)
    subprocess.run(["docker", "push", name], check=True)


def matrix():
    data = load()
    cells = data["cells"]
    out = {
        "primary": tag(next(c for c in cells if c["id"] == data["primary"]), "cpu"),
        "cpu": [{"id": c["id"], "image": tag(c, "cpu")} for c in cells],
        "rocm": [{"id": c["id"], "image": tag(c, "rocm")} for c in cells if c["gpu"]],
    }
    path = CI / "out" / "matrix.json"
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(out, indent=1) + "\n")
    print("ci: wrote %s (%d cpu, %d rocm cells)" % (path, len(out["cpu"]), len(out["rocm"])))


def main():
    command = sys.argv[1] if len(sys.argv) == 2 else ""
    if command == "matrix":
        matrix()
    elif command == "tag":
        print(tag(*selected()))
    elif command == "build":
        build(*selected())
    elif command == "push":
        push(*selected())
    else:
        die("usage: image.py matrix|tag|build|push")


if __name__ == "__main__":
    main()
```

# Lint, typecheck and the GPU-free tests of the freshly built wheel on every

  pull_request:

  contents: read

concurrency:

jobs:
  matrix:

      cells: ${{ steps.read.outputs.cells }}
      primary: ${{ steps.read.outputs.primary }}
    steps:
      - uses: actions/checkout@v4
      - run: pipx install ninja
      - run: ninja -C ci matrix
      - id: read
        run: |
          echo "cells=$(jq -c .cpu ci/out/matrix.json)" >> "$GITHUB_OUTPUT"
          echo "primary=$(jq -r .primary ci/out/matrix.json)" >> "$GITHUB_OUTPUT"

  images:
    needs: matrix
    runs-on: ubuntu-latest

      fail-fast: false
      matrix:
        cell: ${{ fromJSON(needs.matrix.outputs.cells) }}

      - run: pipx install ninja
