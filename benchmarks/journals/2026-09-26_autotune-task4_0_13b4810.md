# Autotune/heuristics Task 4 benchmark gate

Task 4 of the autotune/heuristics plan ("Computed keys and nested levels"), measured
against `2026-09-26_autotune-baseline_0_87c814b.md`.

Measured at commit `13b4810` (Key heuristics over unkeyed values at their level, in
nested maps), clean checkout (this journal is committed after it). Only untuned
launchers are in the suite; the tuned path has no baseline.

Same suite, driver and order as the baseline: `/tmp/intj-bench/run_all.sh task4`, then,
because rows were flagged, `/tmp/intj-bench/run_all.sh task4-rerun` once. Ten cases x
3 rounds = 30 runs each; all 60 report `exit_status=0` and `commit=13b48104...`.
Comparison: `/tmp/gb2/bin/python .superpowers/sdd/2026-09-26-autotune-heuristics/bench_compare.py baseline <label>`.

## Environment

- CPU: x86-64 (224 logical CPUs), `taskset -c 0`, one benchmark process at a time.
  Shared host: load average about 20 at the start of `task4`, 3-13 during
  `task4-rerun`, 13-40 during the A/B, from other users.
- GPU: AMD Instinct MI308X, `gfx942`.
- Python 3.12.3 at `/tmp/gb2/bin/python`; Torch `2.14.0+rocm7.2`; Triton `3.8.0`;
  `apache-tvm-ffi` `0.1.14.post2.dev1+g424558557.d20260924`.
- `INTJ_BENCHMARK_ROOT=/tmp/gbench` (google/benchmark, kernel-cache case only).
- Rendered modules are built by triton at `-O3`; `kernel_cache` builds with `g++ -O3`.

## Verdict

No real regression. The first run flagged 12 rows: all 9 `launch_gpu` rows (+15% to
+26%), `hip_module INTJ same function` and `TVM FFI HIP HSACO` (+3.5%), and
`ffi_paths INTJ pair FFI unpack` (+3.4%). The rerun flagged 3: `ffi_paths INTJ pair FFI
unpack` (+9.7 ns, +3.1%), `ffi_paths INTJ pair direct` (+2.9 ns, +4.4%) and
`launch_gpu bound pointer` (+0.11 us, +3.8%). All are noise:

- **The untuned machine code is unchanged.** Rendering every launcher `bench_launch.py`
  builds (nine contexts, including `bound pointer`) and eight more variants (default
  grid, `grid_cpp`, `grid_py`, `return_compiled`, `bind_device`, INTERPRETER, TSL,
  `grid_arg`+`return_compiled`+`bind_device`) from the `3a96100` and `13b4810` templates
  gives the same non-blank lines. The `bound pointer` module built from both, with the
  same flags and each tree's runtime headers, disassembles byte for byte the same
  (`objdump -d`, addresses included). Task 4's C is emitted only for tuned modules;
  the runtime header only gains unused `static inline` helpers.
- **Rows with no intj code moved as much.** In the first run `hip_module TVM FFI HIP
  HSACO` (no intj) moved +3.6% alongside `INTJ same function` +3.5%.
- **Interleaved A/B** (below) against a worktree of the pre-task commit `3a96100`: `pair
  FFI unpack` +0.3%, `pair direct` -0.4%, the hip_module rows within 1%. `bound pointer`
  came out +3.6% (+104 ns, every pair positive), but its binary is identical to the
  base's, so that is process/placement variance of a GPU submission row, the same
  bimodality Task 3 recorded. Host-only launch rows (`launch_host`, `launch_sweep`,
  `launch_last_key`) are within 3% or 2 ns in both runs.
