# Autotune/heuristics Task 5 benchmark gate

Task 5 of the autotune/heuristics plan ("Invariant test, docs, bench row"), measured
against `2026-09-26_autotune-baseline_0_87c814b.md`. This is the last task, so the
baseline-vs-task5 table below is also the whole plan's cost for untuned launchers.

Measured on the tree committed as `63b42f4` (Pin the tuned key-chain invariant and
document autotune support). The runs were taken on the working tree before that
commit, so the raw outputs say `commit=9dfc698...`; the tree was identical to
`63b42f4` (the formatter had already run). Task 5 changes no file under `intj/`:
`bench_launch.py` only gains the `--tuned` mode, which the suite does not run.

Same suite, driver and order as the baseline: `/tmp/intj-bench/run_all.sh task5`, then,
because rows were flagged, `/tmp/intj-bench/run_all.sh task5-rerun` once. Ten cases x
3 rounds = 30 runs each; all 60 report `exit_status=0`.
Comparison: `/tmp/gb2/bin/python .superpowers/sdd/2026-09-26-autotune-heuristics/bench_compare.py baseline <label>`.

## Environment

- CPU: x86-64 (224 logical CPUs), `taskset -c 0`, one benchmark process at a time.
  Shared host: load average 25 falling to 5 during `task5`, 4-10 during
  `task5-rerun`, from other users.
- GPU: AMD Instinct MI308X, `gfx942`.
- Python 3.12.3 at `/tmp/gb2/bin/python`; Torch `2.14.0+rocm7.2`; Triton `3.8.0`;
  `apache-tvm-ffi` `0.1.14.post2.dev1+g424558557.d20260924`.
- `INTJ_BENCHMARK_ROOT=/tmp/gbench` (google/benchmark, kernel-cache case only).
- Rendered modules are built by triton at `-O3`; `kernel_cache` builds with `g++ -O3`.

## Verdict

No real regression, and none is possible from this task's code: nothing under `intj/`
changed since Task 4. The first run flagged 9 non-kernel-cache rows: the 7 `ffi_sweep
FFI empty kernel` rows (+13% to +30%, pure TVM FFI, no intj code), `launch_gpu bound
pointer` (+3.6%) and `launch_gpu verify on` (+3.1%). All 9 are within threshold in the
rerun (-1.7% to +1.1%, `bound pointer` +0.8%, `verify on` +0.9%). The rerun flagged 8
other rows that were clean in the first run: all 6 `ffi_compare` GPU rows, TVM FFI
(+9%, +14%) and INTJ (+15% to +22%) alike, and the two Triton `launch_readme` rows
(+3.2%, +3.3%, Triton's own launcher). No row is flagged in both runs; these are the
between-process GPU-submission swings the Benchmark Gate describes.

`kernel_cache` rows move +5% to +71% (all < 1.1 ns) in both runs, as in Task 4: the
map-only C++ rows are sub-2-ns and bimodal between processes on this shared host,
and the map code is unchanged since Task 1.

**Overall, baseline (`87c814b`) to task5 for untuned launchers:** every host-only
launch row (`launch_host`, `launch_sweep`, `launch_last_key`, `readme_torch_access`,
`ffi_paths` INTJ rows) is within +3% or +2 ns of the baseline in the first run, most
within 1 ns, and the 32-argument sweep rows are 4-5 ns faster. `INTJ hot call (no
callback)` is +2.0 ns (+5.4%), exactly at the 2 ns threshold, and 38.6 ns in the
rerun (+1.4 ns). GPU submission rows are within noise of the baseline in whichever
run was not disturbed. The autotune/heuristics work costs untuned launchers nothing
measurable beyond ~1-2 ns on the host path.
