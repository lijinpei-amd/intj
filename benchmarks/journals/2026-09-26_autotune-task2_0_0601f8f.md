# Autotune/heuristics Task 2 benchmark gate

Task 2 of the autotune/heuristics plan ("Analyze the wrapper chain": pure-Python
`intj/heuristic.py` and `intj/tuning.py`, `analyze()`/`TuningPlan`), measured against
`2026-09-26_autotune-baseline_0_87c814b.md`.

Task 2 adds no runtime code on the launch path: `intj/heuristic.py` and
`intj/tuning.py` are new files that nothing in `intj/launcher.py` or the rendered
template imports yet (Task 3 wires the miss path to them). The benchmark run below
was taken with the working tree at commit `658bd24` (the parent of the task2 commit,
`0601f8f`, "Assign tuning roles to autotune and heuristics layers") because the task2
files were still untracked at run time; this is code-identical to `0601f8f` for
everything the benchmark suite touches, since `0601f8f` only adds those three new
files and does not modify anything the benchmarks import or exercise.

Same suite, driver and order as the baseline and task1: `/tmp/intj-bench/run_all.sh
task2`. No rerun was needed: no row exceeded both the 3% and absolute (2 ns host /
0.1 us GPU-README) thresholds in the slower direction. Ten cases x 3 rounds = 30 runs,
all report `exit_status=0` and `commit=658bd2495fad6e32d9057f3b8207130cbebfad7b`.
Comparison: `/tmp/gb2/bin/python .superpowers/sdd/2026-09-26-autotune-heuristics/bench_compare.py baseline task2`.

  `apache-tvm-ffi` `0.1.14.post2.dev1+g424558557.d20260924`.

- Rendered modules are built by triton at `-O3`; `kernel_cache` builds with `g++ -O3`.

## Verdict

No regression, no rerun needed. Every row's delta against the baseline median either
stayed under the 3% relative threshold, or under the absolute threshold (2 ns for
host/kernel-cache `ns` rows, 0.1 us for GPU/README/FFI-compare/FFI-sweep/hip_module
`us` rows), computed row by row against
`2026-09-26_autotune-baseline_0_87c814b.md`. This is a quieter run than task1's (which
flagged 9 rows and needed a rerun): the largest kernel-cache jump this round
(`2-word key miss/64 absl`, +36.9%) was still only +1.24 ns, under the 2 ns floor, and
the largest `us`-unit jump (`ffi_compare packed nop`, +4.8%) was +0.0069 us, well
under the 0.1 us floor.

New row `hit_child` (task1's addition, a 1-word child map with two entries) has no
baseline entry, as in the task1 journal; consistent across the three kernel-cache
rounds here.
