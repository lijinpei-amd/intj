# 2026-10-12 — NVIDIA (sm_89) first runtime measurements

First run of the CUDA path on an actual NVIDIA GPU. Until now it was
compile-checked only (`README.md`, `AGENTS.md`, `docs/Usage.md` all said so).
This record establishes the sm_89 baseline; it is not a revision comparison.

## Source state

Measured code is HEAD, `9682f5c`, unmodified: `git status` showed no change
under `intj/` or `benchmarks/` at measurement time. The working tree carried no
edits yet — the test and doc changes in this commit were written afterwards, in
response to these runs. `benchmarks/bench_launch.py` has since gained two lines
of module docstring (naming `cuLaunchKernel` alongside `hipModuleLaunchKernel`
in `--readme`'s description); no timing code changed.

## Command

```sh
for i in 1 2 3 4 5; do
  export TRITON_HOME=$(mktemp -d)
  PYTHONPATH=$PWD taskset -c 0 .venv/bin/python \
    benchmarks/bench_launch.py --readme --iters 20000 --batches 7
  rm -rf "$TRITON_HOME"
done
```

Five processes, each with its own empty `TRITON_HOME` (so the `build s` column
is a cold build every time). 20000 calls × 7 batches; each process reports the
median batch, and the tables below take the median of the five processes.

## Reading

- INTJ's host overhead is ~0.12 us: 0.03 us for the zero-volume early-out plus
  ~0.09 us of argument decode and spec key that the early-out skips. Same
  shape as gfx942's ~0.3 us, and the same conclusion.
- `cuLaunchKernel` itself is therefore ~1.2 us (1.34 − 0.12), against
  ~3.0 us for `hipModuleLaunchKernel` on the MI308X. The `grid=(1,)` row
  flatters CUDA for that reason alone.
- `RUNTIME_SHIM` and `STATIC_COMPILE` land within ~2 ns of each other, as on
  AMD; their spread across runs (±4 ns) is larger than the gap between them,
  so this run does not separate them. `INTERPRETER` is ~3.8x either.
- Cold builds are slower here than the MI300X figures in `README.md`
  (1.05 s vs 0.6 s for the shim). Different machine and different compiler;
  not a regression signal.

## Caveats

- Do not compare the triton columns against the gfx942 journals: different CPU
  (Ryzen 9 7950X3D vs the MI308X host) as well as a different driver. Only the
  within-machine INTJ-versus-Triton ratio carries across.
- Host enqueue time, not GPU completion, as for every row in `bench_launch.py`.
- One GPU on this machine, so nothing here exercises multi-device.
- `bench_hip_module_launch.py` is ROCm-only and was not run.

## Test suite

Same environment, `PYTHONPATH=$PWD .venv/bin/python -m pytest tests -q`:
**869 passed, 21 skipped**. The skips are the HIP-only cases, the two-GPU case,
free-threading, the `RUNTIME_SHIM`-only offset tests, and Google Benchmark.

The spec-key invariant was mutation-checked on this backend, per `AGENTS.md`:
forcing the `auto` 16-byte alignment bit off in `entry.c.jinja` (making the key
coarser than Triton's) fails 6 tests, including
`test_spec_key_is_never_coarser_than_triton`. Reverted after.
