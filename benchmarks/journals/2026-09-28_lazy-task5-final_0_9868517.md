# Lazy launchers Task 5 final: 12-case gate suite (index 0)

Task 5 fix round 1 ran the gate suite once, now with 12 cases. It adds `launch_tuned` (`bench_launch.py --tuned`) and
`launch_dynamic` (`--dynamic`, which now has host-only `spec_key` rows) to the 10 cases the lazy plan gated so far.
Main Task 5 journal: `2026-09-28_lazy-task5_0_8d95e66.md`. Baseline: `2026-09-27_lazy-baseline_0_f507cfc.md`.
`--tuned` reference: `2026-09-26_autotune-task5_0_63b42f4.md`.

## Environment

- Candidate: `9868517` (branch `develop`), clean checkout; all 36 files have `exit_status=0` and `commit=9868517...`.
- CPU: `taskset -c 0`, one process at a time. Shared host; load averages `lazy-task5-final` 6.38, 9.77, 8.92 -> 5.52, 8.14, 8.47.
- GPU: AMD Instinct MI308X (`gfx942`), GPU 0 (`HIP_VISIBLE_DEVICES=0`).
- Python 3.12.3 (`/tmp/gb2/bin/python`), Torch `2.14.0+rocm7.2`, Triton `3.8.0`, gcc/cc 13.3.0.
- `INTJ_BENCHMARK_ROOT=/tmp/gbench`. CUDA: untested.

`run_all.sh` and `bench_compare.py` now know the two new cases. A label without them, such as `lazy-baseline`, compares
as `MISSING`.

## Result

**The 10 old cases:** no new regression.
- Flagged in the suite and already accepted: cold compile callback (+308 ns), readme `spec_key` decode (+3 / +7 ns),
  and the 32-argument placement rows (+7..+9 ns). These match the Task 5 gate.
- Also flagged: every `ffi_sweep` `FFI empty kernel` row (+13..+20%). These rows are TVM FFI launching a kernel with no
  intj code involved. Their samples alternate between ~3.7 and ~4.3 us within a run, and the intj `--dynamic` launch
  column rose to ~3.7 us in the same rounds 1-2, so the GPU was slow in that period.
- Rerunning `ffi_sweep` once (3 processes) gives every `FFI empty kernel` row between -4.1% and +1.4% of the baseline.
  None is flagged, so under the gate rule this is not a regression.

**`--tuned`:** unchanged within noise.

| source | tuned hit ns | plain ns | tuned - plain |
|---|---:|---:|---:|
| autotune plan Task 5 (`63b42f4`, 20000 x 7, median of 3 processes) | 3028.6 | 3022.4 | +6.2 |
| lazy-task5-final (`9868517`, 20000 x 9, median of 3 rounds) | 3078.9 | 3057.5 | +21.4 |
| lazy-task5-final per round | 3098.0, 3078.9, 3036.8 | 3057.5, 3078.4, 3026.5 | |

The tuned hit is +50 ns (+1.7%) over the autotune journal. The plain launch of the same kernel moved by +35 ns in the
same processes. The gap between the two, +21.4 ns, lies inside the autotune journal's
per-run range (-8.9..+65.0). No row passes the gate threshold for GPU rows (3% and 0.1 us), so no A/B against
`f507cfc` was run.

What the host-only rows show (these are the `spec_key` medians):
- **Two dynamic options (`num_warps` int, debug bool):** +9.7 ns over `lazy plain`. The fix-round run at
  100000 x 9 gave +6.8 / +8.7 / +9.7 ns. That is above the plan's 2-4 ns estimate: each value goes through the generic
  `intj_decode_value` and adds a kind byte and 8 value bytes to the key. It is reported, not gated, and it applies
  only to launchers that declare `dynamic_options`.
- **A `str` constexpr against an `int` constexpr:** -0.3 ns (87.3 vs 87.6); the fix-round run gave
  +1.4 / +0.4 / +0.4 ns. So -0.3..+1.4 ns, at or below the plan's 1-3 ns (one memo pointer compare).
- **The GPU `launch` column:** rounds 1-2 ran in the same slow-GPU period as `ffi_sweep`. It cannot resolve these
  differences.

### run_all.sh

```bash
#!/bin/bash
# usage: run_all.sh <label>  -- every benchmark, 3 rounds, separate processes, core 0
set -u
label=$1; out=/tmp/intj-bench/$label; mkdir -p $out
cd /mnt/nvme2/jinpli/workspace/home/jinpli/development/intj
PY=/tmp/gb2/bin/python
cases=(
  "launch_gpu|benchmarks/bench_launch.py --iters 1000 --batches 9"
  "launch_host|benchmarks/bench_launch.py --no-gpu --iters 100000 --batches 9"
  "launch_readme|benchmarks/bench_launch.py --readme --iters 1000 --batches 9"
  "launch_sweep|benchmarks/bench_launch.py --sweep --iters 100000 --batches 9"
  "launch_last_key|benchmarks/bench_launch.py --last-key --iters 100000 --batches 9"
  "ffi_compare|benchmarks/bench_ffi_compare.py --iters 1000 --batches 9"
  "ffi_sweep|benchmarks/bench_ffi_compare.py --sweep --iters 1000 --batches 9"
  "ffi_paths|benchmarks/bench_intj_ffi_paths.py --mode all --iters 1000 --batches 9"
  "hip_module|benchmarks/bench_hip_module_launch.py --iters 1000 --batches 9"
  "kernel_cache|-m pytest tests/test_kernel_cache.py -s -q"
  "launch_tuned|benchmarks/bench_launch.py --tuned --iters 20000 --batches 9"
  "launch_dynamic|benchmarks/bench_launch.py --dynamic --iters 20000 --batches 9"
)
for r in 0 1 2; do
  for c in "${cases[@]}"; do
    name=${c%%|*}; args=${c#*|}
    f=$out/round${r}_$name.txt
    {
      echo "commit=$(git rev-parse HEAD)"
      echo "started=$(date -Iseconds)"
      echo "command=PYTHONPATH=\$PWD INTJ_BENCHMARK_ROOT=/tmp/gbench taskset -c 0 $PY $args"
      s=$(date +%s%N)
      PYTHONPATH=$PWD INTJ_BENCHMARK_ROOT=/tmp/gbench taskset -c 0 $PY $args 2>&1
      st=$?
      echo "elapsed_ns=$(( $(date +%s%N) - s ))"
      echo "exit_status=$st"
      echo "ended=$(date -Iseconds)"
    } > $f
  done
done
echo done > $out/DONE
```
