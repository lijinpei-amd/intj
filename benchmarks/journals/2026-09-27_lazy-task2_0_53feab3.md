# Lazy launchers Task 2: `_intj_lazy` and lazy launchers (index 0)

Benchmark gate for Task 2 of `docs/superpowers/plans/2026-09-27-lazy-dynamic-launchers.md`
(every launcher is a swapped `PyCFunction` over an `_intj_lazy.Launcher`; all mutable
launch state per launcher; `module.entry` removed). Baseline:
`2026-09-27_lazy-baseline_0_f507cfc.md`; Task 1: `2026-09-27_lazy-task1_0_5ad90c0.md`.

## Environment

- Candidate: `53feab3d5670c3a6de023994418780e218c5e6af` (branch `develop`), clean checkout.
- Baseline: `f507cfc` (`/tmp/intj-bench/lazy-baseline`). A/B trees: detached worktrees of
  `24bf5d1` (`/tmp/intj-lazy-base`, same code as `f507cfc`) and `9563edf` (Task 1,
  `/tmp/intj-lazy-t1`).
- CPU: `taskset -c 0`, one process at a time. Shared host; load averages (1/5/15 min) at the start
  of `lazy-task2`: `25.02, 9.88, 8.71`; `lazy-task2-rerun`: `1.98, 3.93, 6.33` -> `4.60, 3.90, 5.89`;
  A/B: `4.49, 3.90, 5.87` -> `4.36, 4.06, 5.65`. A/B files log `/proc/loadavg` per process.
- GPU: AMD Instinct MI308X (`gfx942`), GPU 0; tests ran on GPUs 1,2.
- Python 3.12.3 (`/tmp/gb2/bin/python`), Torch `2.14.0+rocm7.2`, Triton `3.8.0`, g++ 13.3.0.
- `INTJ_BENCHMARK_ROOT=/tmp/gbench`. CUDA: untested (no NVIDIA GPU).

`lazy-task2-ab.sh` runs, per round and per tree (24bf5d1, 9563edf, then HEAD), with
`PYTHONPATH=<tree>` and `taskset -c 0`: `benchmarks/bench_launch.py --no-gpu --iters 100000
--batches 9`, `benchmarks/bench_launch.py --last-key --iters 100000 --batches 9` and
`benchmarks/bench_intj_ffi_paths.py --mode all --iters 1000 --batches 9`.
`lazy-task2-cold.py` (source below) times the ffi_paths cold-miss loop with the benchmark's
`override_compile` wrapper and with a compile function installed directly on the module.

Every one of the 60 gate files has `exit_status=0`.

## Result

**Acceptance met.** In the interleaved A/B every untuned launcher without dynamic values is
faster than `24bf5d1`, not just within 1 ns: `auto map` -2.2, `reduced key` -0.8,
`verify off` -1.1, `verify on` -0.4, `baked` -0.8 ns. Task 1's three placement rows are
back: `last_key 32 repeat` 98.2 (24bf5d1 98.9, Task 1 104.3), `32 alternate` 103.1
(103.5, 108.3), `ffi_paths INTJ adapter kwargs` 103.6 (107.6, 109.0). Bound and
fixed-device rows are 0.9-2.4 ns faster than `24bf5d1`.

Flagged in run 1: three `ffi_compare` GPU rows (+4-5%; 11-15% faster than baseline in the
rerun: GPU submission noise), and three rows that repeat in the rerun, all accepted costs of this task:

| row | baseline | lazy-task2 | rerun | why |
|---|---:|---:|---:|---|
| ffi_paths INTJ cold compile callback + cache | 404.6 | 703.8 | 713.7 | per-launcher miss callback (below) |
| launch_readme decode ns, static_compile | 89.7 | 96.6 | 96.7 | `spec_key(launcher, device, *args)` |
| launch_readme decode ns, runtime_shim | 91.1 | 95.9 | 93.5 (+2.6%, below threshold) | same |

- **Cold miss path, +~300 ns per miss (a miss, never a hit).** C now calls the launcher's
  own callback (`_launcher_compile`: its `seen` map, then `module._intj_compile` looked up
  per miss so `override_compile` reaches built launchers), instead of one module-wide
  callback. That is one more Python frame and a `*args` repack; the benchmark's
  `override_compile` wrapper adds another. Split (`lazy-task2-cold.py`, 3 runs): with the
  wrapper 650-676 ns, with a compile function installed directly 583-586 ns, so
  production misses pay ~+180 ns over the old ~400 ns. A real miss also builds a
  `CompilerInput` and usually compiles (microseconds to seconds). Accepted: the per-launcher
  `seen` check and a per-launcher callback are the design.
- **`--readme` decode row changed meaning.** It times `module.spec_key(launcher, 0, *args)`
  (the launcher and device now lead the arguments; the plan's accepted row change). The
  extra `PyCFunction`/owner/device checks cost 5-7 ns, more than the ~1 ns the plan
  guessed. A debug entry point, not the launch path.
- **Row semantics.** `build ms` in `bench_launch.py` rows now adds `module_of(launcher)`
  (the build moved from `make_launcher`/`bind` to the first call); `bind ms` for bound
  rows is therefore sub-millisecond. Neither column is compared by `bench_compare.py`.
  No row was renamed or dropped.

### lazy-task2-cold.py

```python
# cold miss path breakdown: override_compile wrapper vs a direct module compile function
import statistics, sys, time
sys.path.insert(0, "benchmarks")
import torch
from bench_intj_ffi_paths import callback_kernel
from intj import make_launcher
from intj.launcher import module_of, override_compile

tensors = tuple(torch.zeros(1, device="cuda") for _ in range(3))
iters, batches = 1000, 9

def run(install):
    launch = make_launcher(callback_kernel, bind_device=True, no_gpu=True).bind_device(0)
    module = module_of(launch)
    install(module)
    for i in range(100):
        launch(0, 1, *tensors, -(i + 1))
    samples = []
    for b in range(batches):
        start = time.perf_counter_ns()
        for i in range(b * iters + 1, (b + 1) * iters + 1):
            launch(0, 1, *tensors, i)
        samples.append((time.perf_counter_ns() - start) / iters)
    return statistics.median(samples)

def fake(_key, nparams, _device, *_args):
    return 0, 1, 0, nparams

def direct(seen, _key, nparams, _device, *_args):
    return 0, 1, 0, nparams

for _ in range(3):
    print(f"override_compile wrapper  {run(lambda m: override_compile(m, fake)):.1f} ns")
    print(f"direct module function    {run(lambda m: setattr(m, '_intj_compile', direct)):.1f} ns")
```
