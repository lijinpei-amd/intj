# Specialization and kernel-compiler refactor: `dacf21e` vs `20773a3` (index 0)

`2a6f777` moved the spec-key layout and compiler input into `intj/specialization.py`; `20773a3` moved the
miss-to-record path into `intj/compiler.py`. Neither touches the rendered C or the hit path (every `RenderKey`
a test run builds keeps its digest), so this A/B checks that the launch rows did not move.

## Environment

- Baseline `dacf21e` and candidate `20773a3` as `git archive` exports in `/tmp/intj-bench/<commit>` (no local
  changes). Every raw file records its commit and `/proc/loadavg`.
- Xeon Platinum 8480C on `taskset -c 0` (core 0 idle before), MI308X (`gfx942`) GPU 1 via
  `HIP_VISIBLE_DEVICES=1` (GPU 0 was 100 % busy with another user's job; GPU 1 was 0 %). uv venv with Python
  3.12.3, Torch `2.14.0.dev20260804+rocm7.1`, Triton `3.8.0`, default `TRITON_HOME` (warm cache, so `build s`
  is not a cold build). Machine load average 10 at the start, 4 at the end, from other users on its 224 cores.
- 2026-10-29, 16:00 to 16:09 +08:00. CUDA: untested.

## Command

`/tmp/intj-bench/arch_ab.sh`: 3 rounds; each round runs every case on `dacf21e`, then every case on `20773a3`.
Every process: `cd <tree>; HIP_VISIBLE_DEVICES=1 PYTHONPATH=$PWD taskset -c 0 <venv>/bin/python <args>`.

```
launch_gpu      benchmarks/bench_launch.py --iters 1000 --batches 9
launch_host     benchmarks/bench_launch.py --no-gpu --iters 100000 --batches 9
launch_readme   benchmarks/bench_launch.py --readme --iters 1000 --batches 9
launch_sweep    benchmarks/bench_launch.py --sweep --iters 100000 --batches 9
launch_last_key benchmarks/bench_launch.py --last-key --iters 100000 --batches 9
launch_tuned    benchmarks/bench_launch.py --tuned --iters 20000 --batches 9
launch_dynamic  benchmarks/bench_launch.py --dynamic --iters 20000 --batches 9
```

Compared with `/tmp/intj-bench/arch_ab_summary.py` (`bench_compare.parse_file` and its regression rule:
slower by more than 3 % and by more than 2 ns, or 0.1 us), median of the 3 process medians. All 42 files have
`exit_status=0`. Each bench prints the median of its 9 batches; per-batch samples are not printed by
`bench_launch.py`.

## Result

**No regression; 0 of 53 rows flagged.** `20773a3` against `dacf21e`:

| case | rows | Δ % range |
|---|---:|---|
| `launch_host` | 12 | -0.2 .. +0.4 |
| `launch_sweep` | 6 | -0.2 .. +1.0 |
| `launch_last_key` | 6 | +0.0 .. +0.7 |
| `launch_readme` | 7 | -1.5 .. +1.4 |
| `launch_dynamic` | 8 | -0.4 .. +1.5 |
| `launch_tuned` | 2 | -1.4 .. -0.9 |
| `launch_gpu` | 12 | -7.7 .. +0.2 |

Host-only rows moved by at most 0.2 ns (`launch_host`) and 1.3 ns (`launch_sweep` 32 tensor). The GPU enqueue
rows (about 3.1 us) vary by tens of ns between processes; `launch_gpu` verify on read 3.38 us at `dacf21e` and
3.12 us at `20773a3`, which is noise in the faster direction, not a code effect.
