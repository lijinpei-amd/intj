# Lazy launchers Task 3: object constexprs keyed by value (index 0)

Benchmark gate for Task 3 of `docs/superpowers/plans/2026-09-27-lazy-dynamic-launchers.md`
(`str` / `tl.dtype` / JIT-function constexprs keyed by a per-launcher id, per-slot memo).
Baseline: `2026-09-27_lazy-baseline_0_f507cfc.md`; Task 2: `2026-09-27_lazy-task2_0_53feab3.md`.

## Environment

- Candidate: `a6292eb` (branch `develop`), clean checkout. A/B tree: detached worktree of
  `8d634b6` (Task 2 final, `/tmp/intj-lazy-t2`).
- Baseline: `f507cfc` (`/tmp/intj-bench/lazy-baseline`).
- CPU: `taskset -c 0`, one process at a time. Shared host; load averages (1/5/15 min):
  `lazy-task3` start `7.59, 13.97, 12.30`; `lazy-task3-rerun` start `25.74, 11.76, 10.63`,
  end `41.78, 22.61, 14.80`; A/B `26.97, 20.86, 14.46` -> `6.84, 15.49, 13.21` (A/B and
  align64 files log `/proc/loadavg` per process).
- GPU: AMD Instinct MI308X (`gfx942`), GPU 0 (`HIP_VISIBLE_DEVICES=0`); tests ran on GPUs 1,2.
- Python 3.12.3 (`/tmp/gb2/bin/python`), Torch `2.14.0+rocm7.2`, Triton `3.8.0`, g++/cc 13.3.0.
- `INTJ_BENCHMARK_ROOT=/tmp/gbench`. CUDA: untested (no NVIDIA GPU).

## Commands

```bash
HIP_VISIBLE_DEVICES=0 /tmp/intj-bench/run_all.sh lazy-task3
/tmp/gb2/bin/python /tmp/intj-bench/bench_compare.py lazy-baseline lazy-task3

/tmp/intj-bench/lazy-task3-ab.sh                                     # 5 interleaved rounds, 8d634b6 vs HEAD
/tmp/gb2/bin/python /tmp/intj-bench/lazy_ab_t3_summary.py /tmp/intj-bench/lazy-task3-ab
/tmp/intj-bench/lazy-task3-align.sh                                  # 3 rounds, both trees -falign-functions=64
```

`lazy-task3-ab.sh` runs, per round and per tree (8d634b6, then HEAD), with
`PYTHONPATH=<tree>` and `taskset -c 0`: `benchmarks/bench_launch.py` with `--no-gpu`,
`--sweep` and `--last-key`, each `--iters 100000 --batches 9`.
`lazy-task3-align.sh` does the same for `--sweep` and `--last-key` on two more worktrees
of 8d634b6 and a6292eb whose `_build_flags` add `-falign-functions=64` (a local,
uncommitted one-line edit, never committed), each with its own fresh `TRITON_HOME` so
every module is rebuilt.

Every one of the 60 gate files has `exit_status=0`.

## Result

**No regression attributable to Task 3.** The acceptance rows (untuned launchers, `--no-gpu`)
are within 1 ns of Task 2 in the interleaved A/B (`auto map` +0.5, `verify on` -0.4, all
others -0.4..+0.6 ns). Flagged against the baseline in both runs:

| row | baseline | lazy-task3 | rerun | why |
|---|---:|---:|---:|---|
| ffi_paths INTJ cold compile callback + cache | 404.6 | 709.2 | 707.3 | Task 2's accepted per-launcher miss callback (Task 2: 703.8 / 713.7) |
| launch_readme decode ns, static_compile | 89.7 | 95.3 | 97.1 | Task 2's accepted `spec_key(launcher, device, *args)` row (Task 2: 96.6 / 96.7) |
| launch_readme decode ns, runtime_shim | 91.1 | 93.9 | 94.2 | same (Task 2: 95.9 / 93.5) |
| launch_last_key 32 alternate | 103.3 | 112.1 | 112.6 | code placement (below) |
| launch_last_key 32 repeat | 99.0 | 106.3 | 106.9 | code placement |
| launch_sweep 32 int | 105.9 | 113.7 | 113.4 | code placement |

`ffi_paths INTJ pair prebuilt *tuple` flagged in run 1 only (+4.2 ns, +3.1%; +2.1-2.3% in
Task 2's runs), below threshold in the rerun.

**The 32-argument rows: code placement, not code** (the same effect Task 1 recorded). Those
kernels have no constexpr, so Task 3 adds nothing to their launch path: the rendered
`args_32` sources differ only in `#define INTJ_NMEMO 0`, the `intern`/memo lines in
`intj_bound_traverse`/`intj_bound_clear` and `init_bound`'s interner argument. The
disassembly of `intj_call` is identical (7236 lines, 0 differing after masking
addresses) and `intj_bound_entry` has the same size. The grown cold functions ahead of it
move `intj_call` from `0xa6d0` to `0xa760` (`0x10` -> `0x20` mod 64). With
`-falign-functions=64` in both trees the gap closes (last_key 32: +0.3 / -0.2 ns;
sweep 32 int +1.5, 32 tensor +1.7 ns, below both thresholds). Accepted as layout noise, as in Task 1; not fixed here.

## Timing caveats

Shared host (load averages above, up to ~42 during the rerun). GPU submission rows vary
about 20% between processes; host rows are pinned to core 0 but share L3 with other
tenants. The A/B interleaves trees per round to cancel drift.
